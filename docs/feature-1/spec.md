# 打刻メモ機能 — 仕様書

## 概要

打刻（出勤・退勤）時に任意のメモを入力できる機能を追加する。遅刻理由や早退理由などを記録する用途を想定する。

## 機能要件

### FR-1: メモ入力

- 打刻画面の打刻ボタン上部にメモ入力欄（1行テキスト input）を配置する
- 出勤打刻・退勤打刻それぞれでメモを入力できる
- メモの入力は任意（空欄で打刻可能）
- 文字数上限: 200文字
- 改行は不可（1行入力のみ）
- 上限超過時はバリデーションエラーを表示し、打刻を実行しない

### FR-2: メモ保存

- 打刻時にメモを `attendance_records` テーブルに保存する
- 出勤メモ・退勤メモはそれぞれ独立したカラムとして保持する
  - `clock_in_note`: 出勤時メモ (VARCHAR(200), nullable)
  - `clock_out_note`: 退勤時メモ (VARCHAR(200), nullable)

### FR-3: メモ表示

- 当日の打刻記録（TodayRecords）にメモを表示する
- 月次履歴テーブルにメモカラムを追加して表示する
- チーム勤怠画面・全社員勤怠画面でもメモを確認できる
- 閲覧権限: 画面を閲覧できる全ユーザーにメモも表示する
- トランケート: 30文字で切り詰め、ツールチップで全文表示

### FR-4: メモ編集

- 打刻後でもメモを編集できる
- 編集期限なし（いつでも修正可能）
- **認可: 本人のみ編集可能**（管理者も他人のメモは変更不可）
- 編集UI: 当日記録・月次履歴の両方に編集アイコンを配置し、クリックでダイアログを開いて編集する
- メモのクリア: 空文字 `""` を送信するとメモを削除（null に戻す）
- 楽観ロック: **last-write-wins**（version チェックしない。メモ編集は軽微な操作のため競合対策不要）

### FR-5: メモ位置の明確化

- 打刻画面のメモ入力欄は1つ。出勤・退勤で共用する
- 打刻成功後にメモ欄をクリアする
- ステータスに応じて placeholder を変更:
  - 未出勤: 「遅刻理由など（任意）」
  - 勤務中: 「早退理由など（任意）」

## 既存機能との関係

- `attendance_corrections.reason` は勤怠修正申請の理由であり、打刻メモとは別目的
- 打刻メモは `attendance_records` テーブルに直接持たせる（別テーブルにはしない）
- 修正申請フローには影響しない
- 打刻メモは法的証跡ではなく備忘録。変更ログは保持しない

## API 設計

### 破壊的変更について

`employeeId` をクエリパラメータからリクエストボディに移動する（破壊的変更）。
フロントエンドとバックエンドの同時リリースが前提。他クライアントは存在しないため互換対応は不要。

### 変更: 出勤打刻 `POST /api/attendance/clock-in`

リクエストボディを追加:

```json
{
  "employeeId": "UUID",
  "note": "電車遅延のため10分遅刻"
}
```

- `employeeId`: 必須 (既存のクエリパラメータからボディに移動)
- `note`: 任意、最大200文字、改行不可

### 変更: 退勤打刻 `POST /api/attendance/clock-out`

リクエストボディを追加:

```json
{
  "employeeId": "UUID",
  "note": "体調不良のため早退"
}
```

- `employeeId`: 必須 (既存のクエリパラメータからボディに移動)
- `note`: 任意、最大200文字、改行不可

### 新規: メモ編集 `PATCH /api/attendance/{id}/note`

```json
{
  "clockInNote": "電車遅延のため15分遅刻",
  "clockOutNote": null
}
```

- `null` または フィールド省略 = 変更しない
- `""` (空文字) = メモを削除して null に戻す
- 認可: **本人のみ**（`record.employee.id == authenticatedUser.id` をチェック）
- 楽観ロック: 使用しない（last-write-wins）
- レスポンス: 更新後の `AttendanceRecordResponse`
- 認可エラー: 403 Forbidden

### SecurityConfig への追加

```
PATCH /api/attendance/*/note → authenticated()
```

エンドポイント自体は認証済みユーザーに許可し、所有者チェックは Service 層で行う。

### レスポンス変更: `AttendanceRecordResponse`

既存フィールドに追加:

```json
{
  "id": "UUID",
  "workDate": "2025-01-15",
  "clockIn": "2025-01-15T00:00:00Z",
  "clockOut": "2025-01-15T08:00:00Z",
  "clockInNote": "電車遅延のため10分遅刻",
  "clockOutNote": null,
  "corrected": false
}
```

## DB 設計

### テーブル変更: `attendance_records`

追加カラム:

| カラム名 | 型 | 制約 | 説明 |
|---------|---|------|------|
| `clock_in_note` | VARCHAR(200) | NULL許可 | 出勤時メモ（文字数。PostgreSQL の VARCHAR は文字数ベース） |
| `clock_out_note` | VARCHAR(200) | NULL許可 | 退勤時メモ |

Flyway マイグレーション: `V5__add_attendance_notes.sql`

```sql
ALTER TABLE attendance_records ADD COLUMN clock_in_note VARCHAR(200);
ALTER TABLE attendance_records ADD COLUMN clock_out_note VARCHAR(200);
```

## 画面設計

### 打刻画面（AttendancePage）

```
┌─────────────────────────────────┐
│  [部署名] [氏名]                  │
├─────────────────────────────────┤
│  ┌─────────────────────────┐    │
│  │ 遅刻理由など（任意）       │    │  ← input (1行, 200文字上限)
│  └─────────────────────────┘    │
│  文字数: 0/200                   │
│                                 │
│  [現在時刻表示]                   │
│  ステータス: 未出勤               │
│  [ 出勤 ]  [ 退勤 ]             │
├─────────────────────────────────┤
│  本日の打刻記録                   │
│  出勤: 09:00  メモ: 電車遅延  [✎] │  ← 編集アイコン
│  退勤: --:--                    │
└─────────────────────────────────┘
```

- メモ入力は `input[type=text]`（1行、改行不可）
- placeholder はステータスに応じて変更
- 文字数カウンターを表示
- 打刻成功後にメモ欄をクリアする
- 各打刻記録に編集アイコンを表示

### メモ編集ダイアログ

```
┌─────────────────────────────────┐
│  メモ編集                  [×]   │
├─────────────────────────────────┤
│  出勤メモ:                       │
│  ┌─────────────────────────┐    │
│  │ 電車遅延のため10分遅刻     │    │
│  └─────────────────────────┘    │
│                                 │
│  退勤メモ:                       │
│  ┌─────────────────────────┐    │
│  │                         │    │
│  └─────────────────────────┘    │
│                                 │
│  [キャンセル]  [保存]             │
└─────────────────────────────────┘
```

- 当日記録・月次履歴の編集アイコンから開く
- 出勤メモ・退勤メモを1つのダイアログで編集可能
- 空にして保存 → メモ削除

### 月次履歴テーブル

既存カラムにメモカラムを追加:

| 日付 | 出勤 | 退勤 | 勤務時間 | メモ |
|------|------|------|---------|------|
| 1/15 | 09:10 | 18:00 | 8:00 | 出勤: 電車遅延 [✎] |

- 出勤メモ・退勤メモがある場合は「出勤: ...」「退勤: ...」と接頭辞付きで表示
- 30文字でトランケート、ツールチップで全文表示
- 本人の履歴のみ編集アイコンを表示

## バリデーション

| 項目 | ルール | エラーメッセージ |
|------|--------|---------------|
| note | 最大200文字 | 「メモは200文字以内で入力してください」 |
| note | 改行禁止 | フロント側で入力時にブロック（バックエンドは改行文字を除去） |

- フロントエンド: 入力時にリアルタイムでカウント表示、200文字超過で送信不可
- バックエンド: Bean Validation `@Size(max = 200)` で検証。改行文字 (`\n`, `\r`) はトリムする

## 認可まとめ

| エンドポイント | 認可 |
|--------------|------|
| `POST /api/attendance/clock-in` | authenticated() |
| `POST /api/attendance/clock-out` | authenticated() |
| `PATCH /api/attendance/{id}/note` | authenticated() + 本人チェック (Service層) |
| `GET /api/attendance/today` | authenticated() |
| `GET /api/attendance/history` | authenticated() |
| `GET /api/attendance/team` | authenticated() |
| `GET /api/attendance/all` | ADMIN のみ |

## 受け入れ条件

```gherkin
# メモ付き打刻
Given 一般社員がログインしている
When 出勤打刻時にメモ「電車遅延」を入力して打刻する
Then 201が返り、clockInNote が「電車遅延」で保存される

# メモなし打刻
Given 一般社員がログインしている
When メモを空欄のまま出勤打刻する
Then 201が返り、clockInNote が null で保存される

# メモ編集（本人）
Given 社員Aがログインしている
And 自分の打刻レコードが存在する
When メモ編集APIで clockInNote を「更新後」に変更する
Then 200が返り、メモが更新される

# メモ編集（他人 → 拒否）
Given 社員Aがログインしている
When 社員Bの打刻レコードのメモを編集しようとする
Then 403 Forbidden が返される

# メモクリア
Given 出勤メモが「電車遅延」と記録されている
When メモ編集で clockInNote を "" に更新する
Then 出勤メモが null になる

# バリデーション（200文字OK）
Given メモ入力欄に200文字ちょうど入力している
When 打刻ボタンを押す
Then 正常に打刻され、200文字のメモが保存される

# バリデーション（201文字NG）
Given メモ入力欄に201文字入力している
When 打刻ボタンを押す
Then 400 Bad Request が返される
```

## 非機能要件

- メモの内容に対する検索機能は本スコープ外
- メモの入力履歴（変更ログ）は保持しない（最新値のみ保存）
- 打刻メモは法的証跡ではなく備忘録として位置づける
- 絵文字（4バイト文字）は許可する（PostgreSQL VARCHAR は文字数ベースのため問題なし）
